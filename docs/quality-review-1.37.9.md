## 已复现并修复的问题

| 问题 | 原因与修复 |
| --- | --- |
| 同一个 Pro 请求重复计数 | 原去重只比较 network / dom，遗漏 timer；被合并的页面 ID 也没有入库。统一三路计数，记录请求别名；六种事件到达顺序以及跨标签页恢复均有回归。 |
| 连续快速发送或不同模型请求漏计 | 旧网络记录可以反复吞并后续页面事件。改成同标签页、兼容模型、4.5 秒窗口内的一对一配对，并优先选择最近记录；已配对记录不再匹配其他请求。 |
| 关闭 Pro 统计后仍被迟到事件计数 | 计时保存分支只相信旧的 eligible 状态。所有计数入口现在统一检查当前开关。 |
| 浏览器重新启动后新网络请求漏计 | 原持久去重键仅含 Chrome 网络编号。新键加入请求开始时间，避免编号复用与历史索引冲突。 |
| 后台启动时第一条网络请求丢失 | 请求可能早于异步读取设置。监听器同步注册，处理事件等待设置就绪；开关关闭时不解析请求体，较新的开关变更优先于启动快照。 |
| 后台重启后待确认网络请求丢失 | 原待确认状态只在内存。仅将脱敏模型 / 模式等元数据保存到浏览器会话缓存，重新创建观察器后恢复；计数写入失败时保留元数据，允许完成事件重试。 |
| 超过 30 分钟的活跃计时被后台清理 | 清理和恢复仅比较最初发送时间，没有考虑仍在更新的生成心跳。两处统一按最近生成心跳 / 起始时间保留，仍从原始发送时间计算耗时；普通存档不能无限续期。 |
| 一条损坏状态影响其他计时 | 遍历时未校验保存的 site / path。跳过格式不正确的单条状态，其他有效会话继续读取。 |
| 清空日志后旧日志重新出现 | 清空写入没有加入诊断日志串行队列。清空、追加现在有确定顺序，读取也等待已提交的日志任务。 |

## 数据和权限边界

不清空、重算或补写用户已有历史及累计统计。过往错计无法可靠还原，保留原值。没有修改既有套餐额度规则，也没有将本机统计改称官方配额。

网络待确认缓存键为 `aiInputHistoryProNetworkPending`，使用 `chrome.storage.session`，最多 150 条；恢复或接收新请求时淘汰超过 1 小时的元数据，确认处理或关闭功能时清理。只保留模型 / 模式、接口路径、请求编号、标签页编号、时间和脱敏状态，不保存请求正文、提示词、回复、Cookie 或认证凭据。关闭 Pro 计数时不解析请求体。本版没有新增权限；补全之前遗漏的 `webRequest` 和 ChatGPT 必需网站权限披露。
